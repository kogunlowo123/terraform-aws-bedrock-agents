Architecture Reference -- Autonomous AI Agents with Knowledge Bases and Action Groups

Terraform AWS Bedrock Agent Knowledge Base OpenSearch Serverless Lambda S3

Executive Summary

This module provisions AWS Bedrock Agents -- autonomous AI agents that execute multi-step tasks using foundation models, knowledge bases, and custom action groups. It creates a Bedrock Agent backed by a configurable foundation model (default: Claude 3 Sonnet), a Knowledge Base with OpenSearch Serverless vector store for RAG (Retrieval-Augmented Generation), S3-based document storage, Lambda-powered action groups for API integrations, and all required IAM roles with least-privilege policies. The agent is exposed via an alias for stable versioned invocations.

Component Breakdown

Bedrock Agent

  • Agent -- Orchestrates reasoning with foundation model, instruction prompt, and tools
  • Agent Alias -- Stable endpoint ("live") for production invocations
  • Foundation Model -- Claude 3 Sonnet (configurable); supports streaming
  • Instruction -- System prompt defining agent behavior and capabilities

Knowledge Base (RAG)

  • Knowledge Base -- VECTOR type with embedding model (Titan Embed Text v2)
  • S3 Data Source -- Documents stored in versioned, encrypted S3 bucket
  • OpenSearch Serverless -- VECTORSEARCH collection with encryption, network, and data access policies
  • Vector Index -- Configurable field mapping (embedding, text, metadata)

Action Groups

  • Lambda Functions -- Per-action-group functions with configurable runtime, handler, timeout, memory
  • API Schema -- OpenAPI spec via inline payload or S3-hosted schema
  • Bedrock Permission -- Lambda resource policy allowing bedrock.amazonaws.com invocation

IAM Roles

  • Agent Role -- InvokeModel on foundation model + Retrieve/RetrieveAndGenerate on KB
  • KB Role -- InvokeModel on embedding model + S3 read + OpenSearch APIAccessAll
  • Lambda Roles -- Per-action-group with AWSLambdaBasicExecutionRole

Storage

  • S3 Bucket -- Versioned, KMS-encrypted, public access fully blocked

Data Flow

  1. Client application invokes the agent via the Agent Alias using the Bedrock Runtime SDK
  2. Agent receives the user prompt and applies the instruction context
  3. Agent reasons with the foundation model (Claude 3 Sonnet) to determine the next action
  4. If knowledge is needed, agent calls Retrieve/RetrieveAndGenerate on the Knowledge Base
  5. Knowledge Base embeds the query using Titan Embed Text v2 and searches the OpenSearch Serverless vector index
  6. Matching document chunks are returned to the agent for grounded responses
  7. If an API action is needed, agent invokes the appropriate action group Lambda with structured parameters
  8. Lambda executes the action (e.g., order lookup, data retrieval) and returns results to the agent
  9. Agent synthesizes all information and returns a final response to the client

Industry Adaptation

Customer Support

Load support documentation into the S3 knowledge base. Create action groups for order lookup, ticket creation, and account management. The agent provides grounded answers from docs and executes actions via Lambda.

Internal Knowledge Assistant

Ingest company wikis, runbooks, and policies into S3. The agent answers questions using RAG against the knowledge base. No action groups needed for pure Q&A use cases.

Data Processing Pipelines

Define action groups for data transformation, validation, and enrichment. The agent orchestrates multi-step data workflows by chaining Lambda invocations based on natural language instructions.

Healthcare / Regulated

Use customer-managed KMS keys for all encryption. Restrict OpenSearch network policy to VPC endpoints. Enable S3 access logging. Ensure compliance with data residency requirements via region selection.

Production Readiness Checklist

  • Enable foundation model access in Bedrock console (Claude 3 Sonnet)
  • Enable embedding model access in Bedrock console (Titan Embed Text v2)
  • Upload documents to the S3 knowledge base bucket
  • Trigger knowledge base sync: aws bedrock-agent start-ingestion-job
  • Test agent via Bedrock console Test pane or SDK
  • Verify Lambda action groups execute correctly
  • Review OpenSearch Serverless collection metrics
  • Set up monitoring/alerting on Lambda errors and agent invocation failures
  • Configure remote Terraform state backend (S3 + DynamoDB)
  • Tag all resources with Environment, Team, ManagedBy
